Recall Twig: Application class

回顾 Twig：Application 类
原文 · Original

Recall Twig: Application class

  • The Application class provide the run() method to render the page
  • The Application class contain part of decision logic and page-generation action
  • Separate Controller(s) classes can be implemented
  • Each page of our web pages are unique while having common parts
  • Multiple Controller classes may be needed
截图 1 · 图片文字识别 OCR▾
namespace Mattsmithdev;

use Twig\Loader\FilesystemLoader;
use Twig\Environment;

class Application
{
    const PATH_TO_TEMPLATES = __DIR__ . '/../templates';

    private Environment $twig;

    public function __construct()
    {
        $loader = new FilesystemLoader(self::PATH_TO_TEMPLATES);
        $this->twig = new Environment($loader);
    }

    public function run()
    {
        $meals = [
            'breakfast' => 'toast',
            'lunch' => 'salad',
            'dinner' => 'fish and chips'
        ];

        $product1 = new Product();
        $product1->setDescription('bag of nails');
        $product1->setPrice(10.99);

        $template = 'demo.html.twig';
        $args = [
            'name' => 'matt',
            'meals' => $meals,
            'product' => $product1
        ];

        $html = $this->twig->render($template, $args);
        print $html;
    }
}

Abstract Method, Interface, Trait

抽象方法、接口与 Trait
原文 · Original

Abstract Method, Interface, Trait

  • An abstract method is a method on a superclass that doesn’t have an implementation.
  • It declares the method’s signature: name, parameters, and return type.
  • Any subclasses must provide their own implementation
  • If a class declares one or more abstract methods, the class itself must also be abstract
  • An interface is a way to declare the signatures of one or more methods that a class should have.
  • Classes then implement the interface by declaring methods
  • Interfaces aren’t classes. They are independent of any class hierarchy
  • A trait is a way to provide default versions of methods that are shared among multiple, unrelated classes.
  • This feature offers not just the method signatures, but actual method implementations that can be overridden by the subclasses

Read Chapter 26 and Chapter 25 (Static Methods, Class Constant)

中文翻译 · 中文

抽象方法、接口与 Trait

  • 抽象方法是父类中没有实现体的方法。
  • 它只声明方法的签名：名称、参数和返回类型。
  • 任何子类都必须提供自己的实现。
  • 如果一个类声明了一个或多个抽象方法，这个类本身也必须声明为抽象类。
  • 接口用于声明某个类应当具备的一个或多个方法的签名。
  • 类通过声明这些方法来实现（implement）接口。
  • 接口不是类，它独立于任何类层次结构。
  • Trait 用于为多个互不相关的类提供方法的默认实现版本。
  • 这一特性不仅提供方法签名，还提供可被子类覆盖的真实方法实现。

Relational Database Concepts

关系型数据库概念
原文 · Original

Relational Database Concepts

  • Relational – Our data composed of a set of interrelated tables
  • Tables – Representation of entity.
  • Columns – Represents entity’s attributes. Each column has a unique name and a data type.
  • Rows – Represents a single instance of entity. Also called records.
  • Values – The data stored in the table.
  • Keys – Establish relationship between tables. It uniquely identify rows in a table, and any corresponding rows in other tables
  • Schemas – Like the blueprint of a database, this is the complete set of table designs
  • Relationships – represented as foreign keys these are design implicit and dictate how tables are related to each other.
  • Integrity – The correctness of the database that is maintained by assigning a unique key to each row
  • Referential Integrity – maintain a stable relationship between one table and another
中文翻译 · 中文

关系型数据库概念

  • 关系型（Relational）：数据由一组相互关联的表组成。
  • 表（Tables）：实体的表示。
  • 列（Columns）：表示实体的属性，每列都有唯一的名称和数据类型。
  • 行（Rows）：表示实体的一个实例，也称为记录（record）。
  • 值（Values）：表中存储的数据。
  • 键（Keys）：建立表与表之间的关系，唯一标识表中的行以及其他表中的对应行。
  • 模式（Schemas）：如同数据库的蓝图，是全部表设计的完整集合。
  • 关系（Relationships）：以外键表示，隐含在设计之中，规定表与表如何关联。
  • 完整性（Integrity）：通过为每一行分配唯一键来维护数据库的正确性。
  • 参照完整性（Referential Integrity）：维护表与表之间稳定的关联关系。

P10

OOP Mapping to Database

面向对象到数据库的映射
原文 · Original

OOP Mapping to Database

  • OOP web applications with a database is implemented by designing a class that corresponds to each table in the database.
  • These entity classes have properties mirroring the table’s columns,
  • an instance of the class corresponds to a record (row) of the table.
  • Writing data to a database table:
  • create an object of the appropriate class containing the new data
  • use the database connection to send the object’s data to the database table.
  • a new unique key for the new record can be sent back to the web application and stored in the corresponding object for future reference.
  • Reading data from a database table:
  • read the retrieved data into a new object of the appropriate class
  • entity-relationship (ER) model can be created to show the database relational’s schema
中文翻译 · 中文

面向对象到数据库的映射

  • 带数据库的 OOP Web 应用，其实现方式是让每一个类对应数据库中的一张表。
  • 这些实体类的属性与表的列一一对应。
  • 类的一个实例对应表中的一条记录（行）。
  • 向数据库表写入数据：
  • 创建相应类的对象，其中装入新数据。
  • 通过数据库连接把对象的数据发送到数据库表。
  • 新记录的唯一键可以返回给 Web 应用，并存入相应对象以备后用。
  • 从数据库表读取数据：
  • 把取出的数据读入相应类的一个新对象。
  • 可以建立实体—关系（ER）模型来展示数据库的关系模式。

The Model-View-Controller Pattern

MVC（模型—视图—控制器）模式
原文 · Original

The Model-View-Controller Pattern

  • The classes corresponding to the database tables are part of the model component of the application
  • The action controller classes communicate with (read from and modify) the model classes.
  • Utilizing the OO classes that communicate with the database.
  • Database interactions are kept completely separate from the controller and view components of the application.
  • We could change the underlying database without having to make any changes to the front controller, the action controller classes, or the templates.

MVC（模型—视图—控制器）模式

  • 与数据库表对应的类属于应用的模型（model）组件。
  • 动作控制器类负责与模型类通信（读取与修改）。
  • 利用这些与数据库通信的面向对象类。
  • 数据库交互与应用的控制器、视图组件完全分离。
  • 更换底层数据库时，无需修改前端控制器、动作控制器类或模板。
